## 1. Executive Summary

This forensic investigation was commissioned to determine the root causes of two critical failures in the BOURXE platform:
1. **Issue 1:** Repeated document save failures logged on the Dashboard (`/`) on 17 November 2026, alongside persistent settings operation failures logged on `/settings` on 16 November 2026.
2. **Issue 2:** Failure of the Bolu conversational assistant to submit, process, or regenerate responses when a user edits a previously submitted message in the chat thread.

### Key Forensic Findings

1. **Diagnostic Information Loss in `feedback.ts`:**
   In [src/lib/feedback.ts](file:///c:/Users/DELL/Desktop/bigdrops-app/src/lib/feedback.ts#L86-L100), `feedback.error(message, options)` calls `normalizeError(message)` and passes the resulting strings to `errorRegistry.add()`. The function receives `options.description` (which contains the raw PostgreSQL error message or RPC failure reason), but **completely ignores `options.description`** when recording the diagnostic entry. When callers execute `feedback.error('Save failed', { description: result.error })`, the error registry records `'Save failed'` as both the title and the diagnostic message, swallowing the underlying SQL, RPC, and HTTP error details.

2. **Root Cause of 17 November Save Failures (`/`):**
   The two events at `10:09:26.693Z` and `10:09:30.270Z` (3.58 seconds apart) represent an initial user click and an immediate user retry of the **Gate 2 Save** action on document draft `QTN-DRAFT`. The save failed in `confirmGate2Save` ([src/lib/ai-assistant/hooks/useBoluThread.ts#L508-L626](file:///c:/Users/DELL/Desktop/bigdrops-app/src/lib/ai-assistant/hooks/useBoluThread.ts#L508-L626)). The failure occurred during either the `/api/bolu-save` endpoint execution or the fallback RPC call `save_quotation_with_items_transaction` due to schema resolution fallback (`'public'` instead of tenant schema) or a non-conforming proposal payload generated by the model (specifically an invalid `extra_charges` key injected into the draft, as evidenced in conversation screenshots).

3. **Root Cause of 16 November Settings Failures (`/settings`):**
   The string `"The operation failed. Retry, or review the server logs."` originates exclusively from the catch-all error handler of the Vercel serverless function at [api/bolu-provider-config.ts#L301-L304](file:///c:/Users/DELL/Desktop/bigdrops-app/api/bolu-provider-config.ts#L301-L304). The client at [src/pages/settings/bolu-provider/api.ts#L191-L194](file:///c:/Users/DELL/Desktop/bigdrops-app/src/pages/settings/bolu-provider/api.ts#L191-L194) received HTTP 500 when attempting to test, discover models on, or create a custom endpoint connection (Runcrate / Bolucrate), triggered because the custom endpoint was either unreachable, returned non-200, or encountered encryption secret misconfiguration.

4. **Root Cause of Bolu User Message Edit/Send Failure:**
   The failure of user message editing is caused by **a multi-layer UI lockout and silent error suppression defect**:
   - **Form Lockout during Proposal Gate:** When a proposal is in `pending_approval` or `approved_pending_save` (or when a save failure leaves `clerkState` as `'listening'`), `useBoluThread` sets `clerkState = 'listening'`. In [BoluChatWorkspace.tsx#L417](file:///c:/Users/DELL/Desktop/bigdrops-app/src/components/ai-assistant/chat/BoluChatWorkspace.tsx#L417), the composer receives `disabled={isStreaming || clerkState !== 'idle'}`. In [assistant-chat-composer.tsx#L44-L100](file:///c:/Users/DELL/Desktop/bigdrops-app/src/components/ai-assistant/chat/assistant-chat-composer.tsx#L44-L100), `isLocked = busy || Boolean(disabled)`. Even when the user enters edit mode (`editing = true`), `isLocked` remains `true` because `clerkState !== 'idle'`. The textarea is locked, and the submit button is rendered `<button type="submit" disabled={!value.trim() || isLocked}>`, making it unclickable.
   - **Silent Error Suppression:** `useBoluThread` exports `error`, but [BoluChatWorkspace.tsx#L216-L230](file:///c:/Users/DELL/Desktop/bigdrops-app/src/components/ai-assistant/chat/BoluChatWorkspace.tsx#L216-L230) **does not destructure or render `error`**. When `editUserMessage` fails (e.g. due to Supabase RLS update restriction, tenant mismatch, or network timeout), `handleSaveEdit` in [useBoluChatInteractions.ts#L78-L88](file:///c:/Users/DELL/Desktop/bigdrops-app/src/hooks/useBoluChatInteractions.ts#L78-L88) does not show a toast and leaves the draft stuck in the composer without feedback.

## 4. 17 November Save Failure Findings

### 4.1 Route Context and User Action Sequence
- **Route:** `/` (Dashboard).
- **UI State:** The Bolu assistant slide-over drawer / bottom-sheet was open over the dashboard view.
- **Document Under Mutation:** Quotation draft `QTN-DRAFT`, client `"Tecno Power Solutions"`, total `₦11,825` (line items: 1.5mm electrical cable 10 rolls @ ₦700 = ₦7,000; 2.5mm electrical cable 5 rolls @ ₦800 = ₦4,000; VAT 7.5% = ₦825).
- **Event Timing:** Event 2 logged at `10:09:26.693Z`. Event 1 logged at `10:09:30.270Z` (exactly 3.577 seconds later). This confirms an immediate user retry of the Gate 2 save button after the first failure toast appeared.

### 4.2 End-to-End Execution Trace
1. **User Interaction:** User taps "Approve Changes (Gate 1)", placing the proposal into `status: 'approved_pending_save'`. The user then clicks the Gate 2 confirmation button or types a natural-language save command.
2. **Hook Execution:** `confirmGate2Save` is triggered in [src/lib/ai-assistant/hooks/useBoluThread.ts#L487](file:///c:/Users/DELL/Desktop/bigdrops-app/src/lib/ai-assistant/hooks/useBoluThread.ts#L487).
3. **Primary Save Attempt (`/api/bolu-save`):**
   - The client performs a `POST /api/bolu-save` with `{ proposal, tenantId, entityId, conversationId, proposalMessageId }`.
   - In [api/bolu-save.ts#L59-L65](file:///c:/Users/DELL/Desktop/bigdrops-app/api/bolu-save.ts#L59-L65): If `SUPABASE_SERVICE_ROLE_KEY` is not present in Vercel environment variables, `getAdminClient()` returns `null`, and the endpoint responds with HTTP 500 `{ error: 'Server configuration error: missing Supabase admin client.', code: 'server_config_missing' }`.
   - In [api/bolu-save.ts#L112-L115](file:///c:/Users/DELL/Desktop/bigdrops-app/api/bolu-save.ts#L112-L115): If `entities` lookup fails or returns no schema, `schemaName` defaults to `'public'`. Attempting to call `.schema('public').rpc('save_quotation_with_items_transaction')` fails with PostgreSQL error `function public.save_quotation_with_items_transaction does not exist`.
4. **Client Response Handling:**
   - In [useBoluThread.ts#L524-L530](file:///c:/Users/DELL/Desktop/bigdrops-app/src/lib/ai-assistant/hooks/useBoluThread.ts#L524-L530): Because the server returned HTTP 400 or 500 (not 404), `result` is assigned `{ success: false, error: errData?.error }`.

5. **UI Error Handling & Masking:**
   - [useBoluThread.ts#L624](file:///c:/Users/DELL/Desktop/bigdrops-app/src/lib/ai-assistant/hooks/useBoluThread.ts#L624): `feedback.error('Save failed', { description: result.error || 'Failed to save document.' })` is called.


3. **Database RLS Rejection on `app_ai_provider_connections`:** If the user's Supabase JWT does not satisfy the `is_workspace_owner_or_admin` check on `public.app_ai_provider_connections`, Supabase rejects the write with error code `42501`.

## 6. Database and Migration Findings

### 6.1 Assessment of the "Pending Migration" Hypothesis
The user hypothesized that a pending SQL migration was causing the save failure.
- **Investigation Outcome:** The hypothesis is **partially confirmed, with important architectural nuance**:
  - `save_quotation_with_items_transaction` is defined in migration [supabase/migrations/20261006120000_tenant_rpc_cps_quotation_transaction.sql](file:///c:/Users/DELL/Desktop/bigdrops-app/supabase/migrations/20261006120000_tenant_rpc_cps_quotation_transaction.sql#L2113) and was updated in `20261106230000_tenant_rpc_purchase_order_transaction.sql`.

  - In [api/bolu-save.ts#L112-L115](file:///c:/Users/DELL/Desktop/bigdrops-app/api/bolu-save.ts#L112-L115), if `entityId` is missing or the tenant schema lookup fails, `schemaName` defaults to `'public'`.   - Furthermore, between 14 Nov and 17 Nov, multiple migrations were added (`20261114170000_bolu_provider_connections.sql`, `20261114180000_bolu_conversation_persistence.sql`, `20261116120000_bolu_conversation_retention.sql`, `20261117000000_release_acknowledgements.sql`). ## 8. Cross-Issue Relationship Analysis

The two reported problems are directly interconnected through Bolu's conversation state machine:

```
[ Gate 1 / Gate 2 Proposal Created ]
                │
                ▼
      clerkState = 'listening'
                │
                ├─────────────────────────────────────────┐
                ▼                                         ▼
   [ Gate 2 Save Triggered ]                [ User Attempts to Edit Message ]
                │                                         │
     Save Fails (DB / Schema / Key)                       ▼
                │                          BoluChatWorkspace passes:
      clerkState stays 'listening'         disabled = (clerkState !== 'idle')
                │                                         │
                ▼                                         ▼
   feedback.error('Save failed')              isLocked = true in Composer
                │                                         │
   Diagnostic swallowed by feedback.ts                    ▼
   (Only "Save failed" recorded in log)     Textarea and Send button LOCKED!
                │                                         │
                ▼                                         ▼
   Proposal remains pending save ──────────> User CANNOT resubmit or regenerate!
```

1. **State Pinning:** A failed save operation keeps `activeProposal` in status `'approved_pending_save'` and sets `clerkState = 'listening'`.
2. **Cascading Lockout:** Because `clerkState` is never reset to `'idle'` after a failed save, the composer remains disabled. Any attempt by the user to edit their previous prompt (e.g. changing `"add to extra charges"` to something the schema accepts) is blocked by the composer's `disabled` prop.
3. **Observability Blackout:** Both failures suffer from silent information loss: `feedback.ts` drops the PostgreSQL error message on save, while `BoluChatWorkspace.tsx` ignores the hook's `error` state on edit.
