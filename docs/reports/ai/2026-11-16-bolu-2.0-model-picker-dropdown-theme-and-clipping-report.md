## 1. Problem Description

A mobile screenshot identified two visual defects in the Bolu 2.0 active AI model picker dropdown:

1. **Visual Surface and Theme Inconsistency:** The dropdown used hardcoded dark styling (`bg-[#181622]`, `bg-[#14121c]`, `border-white/10`, and `text-white`). In light application mode, this appeared as an accidental, unintegrated dark container that conflicted with the BOURXE design system tokens.
2. **Mobile Horizontal Viewport Clipping Defect:** On mobile viewports (e.g. 360px–390px screens), the dropdown container extended beyond the left screen boundary. Model names, provider titles, and badges were clipped on the left edge. The previous static CSS class `right-0` aligned the right edge of the 320px dropdown with the right edge of the model trigger button (`rootRef`). Because compact header action controls (`PanelRight`, `MoreVertical`, `Close`) occupy 80px–110px on the right side of the header, `right-0` placed the left edge of the dropdown at screen coordinates `-50px` to `-70px`, clipping content.

## 2. Technical Remediation

### 2.1 Dynamic Collision-Aware Viewport Clamping

In `src/components/ai-assistant/chat/assistant-chat-model-pill.tsx`, static alignment classes were replaced by a dynamic positioning calculation:

- **Viewport Boundary Calculation:**
  ```ts
  const triggerRect = rootRef.current.getBoundingClientRect()
  const viewportWidth = window.innerWidth || document.documentElement.clientWidth
  const viewportHeight = window.innerHeight || document.documentElement.clientHeight
  const safeMargin = 10

  const targetWidth = Math.min(340, Math.max(260, viewportWidth - safeMargin * 2))
  let idealLeft = triggerRect.right - targetWidth

  // Left boundary collision prevention
  if (idealLeft < safeMargin) {
    idealLeft = safeMargin
  }

  // Right boundary collision prevention
  if (idealLeft + targetWidth > viewportWidth - safeMargin) {
    idealLeft = viewportWidth - safeMargin - targetWidth
  }

  const relativeLeft = idealLeft - triggerRect.left
  ```
- **Collision Prevention Verification:** On a 360px viewport with `triggerRect.right = 260px`, the computed screen X coordinates are clamped to `[10px, 350px]`. The dropdown cannot extend beyond either edge of the display.
- **Event Listeners:** The positioning calculation executes on dialog open and updates on window resize, device orientation change, and document scroll.

### 2.2 Theme-Adaptive Visual Surface

Replaced hardcoded arbitrary dark colors with BOURXE theme-aware slate and warm amber styling:

- **Dropdown Container:** Elevated surface using `bg-white dark:bg-slate-900 border border-slate-200/90 dark:border-slate-800 text-slate-900 dark:text-slate-100 shadow-2xl backdrop-blur-md`.
- **Search Header Bar:** `bg-slate-50 dark:bg-slate-950/80 border-b border-slate-200 dark:border-slate-800` with input `text-slate-900 dark:text-slate-100 placeholder:text-slate-400 dark:placeholder:text-slate-500`. Quick action buttons use theme-aware hover transitions.
- **Group Headers:** `text-amber-500 dark:text-amber-400 font-semibold text-xs tracking-wide`.
- **Model Item Options:** Unselected items use `text-slate-700 dark:text-slate-300 hover:bg-slate-100 dark:hover:bg-slate-800/80`. Selected items render `bg-amber-500/15 dark:bg-amber-500/20 text-amber-950 dark:text-amber-200 font-semibold border border-amber-500/30 dark:border-amber-500/40`.
- **Badges:** Free badge uses `bg-slate-100 dark:bg-slate-800 text-slate-600 dark:text-slate-300 border border-slate-200 dark:border-slate-700`.
- **Footer Bar:** `bg-slate-50 dark:bg-slate-950/80 border-t border-slate-200 dark:border-slate-800` with Manage action in `text-amber-600 dark:text-amber-400`.
