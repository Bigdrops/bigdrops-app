## Changes Made

### 1. Viewport Adaptation & Workspace Architecture
- Mapped breakpoints to Design Lab standards: `<768px` (Phone/Fold Closed), `768px–1023px` (Fold Open), `1024px–1279px` (Tablet), and `>=1280px` (Desktop).
- Streamlined header in `assistant-chat-chrome.tsx`. Replaced the oversized mark with a compact badge and pill. On mobile, grouped Model Selector, Export Markdown, Export JSON, and Settings into a `MoreVertical` dropdown.
- Restored conversation history rail access in fold-open mode to prevent user lockout.
- Added drawer overlay behavior for mobile and tablet viewports to prevent layout squashing.
- Redesigned `assistant-chat-panel.tsx` with explicit collapse support and business-focused empty states.

### 2. Conversation Lifecycle & Realtime Synchronization
- Updated `useBoluConversations.ts` with `autoSelectLatest = false` by default. Bolu opens into a fresh empty session without automatic thread selection.
- Applied lazy thread creation. Conversation rows persist only after the user submits the first prompt.
- Removed route-module filtering (`.eq('module', ...)`). Users can access operational conversations from any authorized route.
- Added Supabase Realtime channel listener in `useBoluThread.ts` to receive incoming messages on active threads.
- Compacted imports and hook dependencies to keep `useBoluThread.ts` at 599 lines, complying with the 600-line load-risk ceiling.

### 3. Database Retention & Scheduled Expiration
- Added column `scheduled_deletion_at timestamptz` and index `idx_bolu_conversations_user_retention` on `public.bolu_conversations`.
- Created trigger `enforce_bolu_conversation_limit()` on `BEFORE INSERT`:
  - Acquires a transaction-level advisory lock using `pg_advisory_xact_lock(hashtext('bolu_retention_' || NEW.user_id::text))`.
  - Enforces a global cap of 10 active conversations per user across all workspaces.
  - When the 11th active conversation is inserted, marks the oldest active conversation with `scheduled_deletion_at = NOW() + INTERVAL '48 hours'`.
- Created `restore_bolu_conversation(p_conversation_id uuid)` RPC function:
  - Validates user ownership and pending expiration.
  - Clears `scheduled_deletion_at`.
  - Evicts the oldest thread if restoring exceeds the 10-conversation cap.
- Created `cleanup_expired_bolu_conversations()` function that hard-deletes expired conversations and cascaded messages.
- Scheduled hourly cron job `'bolu-retention-cleanup'` at minute 15 using `cron.schedule`.

## Risks or Limitations

- The 10-conversation cap is global per user ID. If an operator switches between distinct company workspaces frequently, the cap applies across their entire account rather than per workspace tenant.
- Hourly cron execution runs at minute 15. Expired conversations may persist for up to 59 minutes past their 48-hour mark before the cron job cleans them.
