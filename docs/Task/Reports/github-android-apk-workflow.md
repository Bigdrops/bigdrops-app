## Architecture Summary

## Decisions Made

### 1. Workflow Trigger: `workflow_dispatch` with optional `ref` input
- Allows manual execution from GitHub web interface
- Optional `ref` input lets staff build any branch, tag, or SHA
- Defaults to the repository's default branch

### 2. Runner: `ubuntu-latest`
- GitHub-hosted Ubuntu runners have sufficient RAM and CPU for Gradle builds
- Avoids the local machine's RAM limitations

### 3. Java Distribution: Temurin (Eclipse Adoptium)
- Widely used, well-tested, LTS support
- Version 21 matches `compileOptions` in `android/app/build.gradle`

### 4. Caching Strategy
- **Gradle:** Handled by `actions/setup-java@v4` with `cache: gradle`
- **Bun:** Custom cache at `~/.bun/install/cache` keyed on `bun.lock`
- **No npm cache needed** — project uses Bun exclusively

### 5. APK Path Detection
- Uses `find` command to locate APK in `android/outputs/apk/*` rather than hardcoding
- Fails with clear error if no APK found

### 6. Concurrency Control
- `concurrency` group prevents parallel builds on the same branch
- `cancel-in-progress: true` avoids wasting runner minutes

### 7. No Secrets Required
- Debug APK uses default debug keystore (auto-generated by Android SDK)
- No signing credentials needed
- No Firebase or Play Store deployment

## Workflow Stages

1. **Checkout** — Clone repository at specified ref
2. **Validate** — Fail early if android/, gradlew, or wrapper properties are missing
3. **Java 21** — Setup JDK with Gradle caching
4. **Bun** — Setup Bun runtime with dependency caching
5. **Install** — `bun install --frozen-lockfile`
6. **Web Build** — `bun run build` (produces `dist/`)
7. **Capacitor Sync** — `npx cap sync android` (copies web assets + generates plugin config)
8. **Gradle Build** — `./gradlew assembleDebug --no-daemon --stacktrace`
9. **Locate APK** — Find generated APK file dynamically
10. **Upload** — Artifact uploaded with 30-day retention

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| `google-services.json` contains API keys | Low | Committed to repo (already was). Consider moving to secrets for production. |
| Bun lockfile format may change | Low | Cache key uses `bun.lock` hash; fallback restore key ensures partial cache hit. |
| Gradle cache size on GitHub runners | Low | GitHub limits cache to 10GB total. Gradle caches are incremental. |
| `assembleDebug` may fail if dependencies change | Medium | Workflow validates prerequisites early; `--stacktrace` provides detailed error output. |
| Workflow timeout (30 min) | Low | Typical builds complete in 10-15 minutes. 30 min provides headroom. |

## How to Use

1. Push code to the repository (ensure `android/` and `google-services.json` are committed).
2. Go to GitHub → Actions → "Build Android Debug APK".
3. Click "Run workflow".
4. Optionally specify a branch/tag/SHA in the `ref` field.
5. Wait for the workflow to complete.
6. Download the APK from the workflow run's "Artifacts" section.

## Summary

The GitHub Actions workflow at `.github/workflows/build-android-debug.yml` enables manual Android Debug APK builds on GitHub-hosted runners. No local Gradle build is required, no signing secrets are needed, and the APK is downloadable as a workflow artifact with 30-day retention. The implementation follows all project conventions (Bun runtime, no application logic changes) and includes early validation, dependency caching, and clear error reporting.
