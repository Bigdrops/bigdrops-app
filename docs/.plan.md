# Receipt Module Correction Plan — per prompt1rcp2.md

## Context

The initial receipt implementation (prior session) created a basic scaffolding that violates the receipt standard (`docs/STANDARD/receipt-standard.md`) in multiple critical ways:

1. **No snapshot columns** — Receipts don't freeze client, invoice, payment, or company data at creation time
2. **No `withUniqueRetry`** — Receipt number generation has no idempotency protection against race conditions
3. **No `RECEIPT_GENERATED` audit event** — Payment service doesn't emit the required audit event
4. **PDF is not a dumb renderer** — It computes data instead of receiving a fully-shaped `ReceiptPreviewData`
5. **Missing snapshot builder** — No pure function to build the frozen data snapshot
6. **Incomplete immutability guard** — Only 9 fields checked, should be 19+
7. **Incomplete preview model** — Missing amount-in-words, terms, signature block
8. **Settings UI missing `'receipt'` prefix key** — Not registered in `PREFIX_KEYS`, `LABELS`, `PREFIX_INFO`, `PREVIEW_TEMPLATES`
9. **Missing audit event constants** — No `RECEIPT_GENERATED` or `RECEIPT_VOIDED`

## Execution Plan

### Step 1: Create snapshot builder — `src/domain/receipt/snapshotBuilder.ts`

New file. Pure function `buildReceiptSnapshot()` that accepts fetched invoice/client/company/payment data and returns a flat object with all frozen fields per §3.2 of the standard:
- Client snapshot: `client_name`, `client_email`, `client_phone`, `client_address`
- Invoice snapshot: `invoice_number`, `invoice_date`, `invoice_due_date`, `invoice_total`, `invoice_balance_due`
- Payment snapshot: `payment_amount`, `payment_method`, `payment_date`, `payment_reference`
- Company snapshot: `company_name`, `company_address`, `company_phone`, `company_email`, `company_logo_url`

This function is a pure data mapper — no DB calls, no side effects.

### Step 2: Expand `ReceiptRow` type — `src/domain/receipt/types.ts`

Add all snapshot columns to `ReceiptRow` interface:
- `voided_at: string | null`
- Client snapshot: `client_email`, `client_phone`, `client_address`
- Invoice snapshot: `invoice_number`, `invoice_date`, `invoice_due_date`, `invoice_total`, `invoice_balance_due`
- Company snapshot: `company_name`, `company_address`, `company_phone`, `company_email`, `company_logo_url`

### Step 3: Expand `CreateReceiptInput` — `src/domain/receipt/receiptRepository.ts`

Add all snapshot fields to `CreateReceiptInput` interface (same fields as Step 2 minus auto-generated fields).

### Step 4: Create DB migration — `supabase/migrations/20260707000000_receipt_snapshot_and_idempotency.sql`

Adds snapshot columns to `receipts` table:
- `voided_at timestamptz`
- Client: `client_email`, `client_phone`, `client_address`
- Invoice: `invoice_number`, `invoice_date`, `invoice_due_date`, `invoice_total`, `invoice_balance_due`
- Company: `company_name`, `company_address`, `company_phone`, `company_email`, `company_logo_url`
- CHECK constraint for `settings.document_prefixes` to include `'receipt'` key
- CHECK constraint for `activity_events.entity_type` to include `'receipt'`

### Step 5: Rewrite receipt creation — `src/modules/invoices/services/paymentService.ts`

Replace the current receipt creation block (lines ~117-149) with:
1. Fetch invoice + client + company + settings in parallel
2. Call `buildReceiptSnapshot()` with fetched data
3. Use `withUniqueRetry` wrapping `insertReceipt` for idempotent number generation
4. Emit `RECEIPT_GENERATED` audit event with `payment_id` in `payload.before`

### Step 6: Expand immutability guard — `src/domain/receipt/assertReceiptImmutable.ts`

Extend the `frozen` array to include all 19+ snapshot fields per §1.2 and §3.3 of the standard. Add `voided_at` to the immutable set.

### Step 7: Rewrite preview model — `src/domain/receipt/previewModel.ts`

Replace `ReceiptPreviewModel` with canonical `ReceiptPreviewData` per §4.1 of the standard. The model must be shaped directly from the receipt row (all data comes from snapshot columns). Add `amountInWords` field (computed here, not in PDF).

### Step 8: Rewrite PDF — `src/components/pdf-new/ReceiptPdf.tsx`

Full rewrite as a dumb renderer that receives `ReceiptPreviewData` and renders all 8 required sections per §7.1:
1. Header — company logo, receipt number, title
2. Client snapshot — name, email, phone, address
3. Payment snapshot — amount, method, date, reference
4. Amount in words — from `amountInWords` field
5. Notes
6. Terms — verbatim from §8 of the standard
7. Signature block
8. Footer

### Step 9: Add audit event constants — `src/lib/audit.ts`

Add `RECEIPT_GENERATED` and `RECEIPT_VOIDED` event type constants and `recordReceiptGenerated()` helper function.

### Step 10: Register `'receipt'` in settings UI — `src/pages/settings/DocumentPrefixesSettingsSection.tsx`

Add `'receipt'` to:
- `PREFIX_KEYS` array
- `LABELS` record (label: `'Receipt'`)
- `PREFIX_INFO` record (title/description)
- `PREVIEW_TEMPLATES` record (template: `(p) => [\`${p}-000001\`]`)
