The provider constraint, stated correctly

No provider supports tenancy. That is not a property that exists. Every provider is one API key with one quota. The app can call any OpenAI-compatible endpoint from any form.

The real constraint is legal and economic, and it has two shapes.

ShapeWho holds the keyUsable for
Tenant’s own keyThe tenant, in private storageThe shipping path. Any document, any tenant.
Vendor pools one keyThe vendorA demo, an internal trial, or a paid plan.

The pooled shape fails twice. One free quota would serve every tenant, so the first busy day exhausts it. And several free tiers call themselves a trial or development service and forbid resale — the AMD Token Factory says so directly. That is the vendor’s key, not a missing provider feature.

Trial

GFour weeksMeasured per document, not as one number›
  • Week 1. Five invoices, three quotations, two waybills by conversation. The first error list, per document.
  • Week 2. Fix the top three errors. Measure both paths again.
  • Week 3. Daily use across the set. Add the PO and CSR packs.
  • Week 4. Measure again and write the decision.
The only two measures
  • Time from opening a document to saving it: median 90 seconds or less.
  • Manual corrections: fewer than 1 per 20 documents by week 4.

Watch: RISK-13. One number for the whole set hides a pack that is failing.

Decision

  1. KEEP Choose the shipping shape: tenant keys, or a paid production provider.
  2. CHANGE Return to the failing pack. The engine does not repeat.
  3. REMOVE Toggle and module go. Every form still works. No tenant data exists to delete.

Open points

Blocks stage A

One provider order

The PRD lists NVIDIA first. Two decisions put Cloudflare first and AMD second. The first catalog row is the first call of every turn.

Blocks the gate

Where the new tests run

The test script runs the critical folder only. A test that never runs is not a gate.

Blocks readiness

Trial audience

Product owner only, or the whole test tenant. The disclosure and the terms risk both depend on it.

Product

Pack order, record creation, document numbers

Money first is this roadmap’s choice. Whether the assistant may create a client or supplier record, and change a document number, is still open.

Two ways to shorten the build

Ten days is the plan. If that is too long, pick one and say so.

  • Money documents first. Five days: engine, invoice, quotation. The other six packs wait.Trial measures two documents
  • Start the trial when the first pack passes. The gate moves later and the trial measures a moving target.RISK-13 gets worse

Not in this roadmap

Photo, image or scan input. Voice input. Automatic sending to a client, supplier or consignee. A database table for assistant history. Any change to the calculation file or a PDF renderer. The on-device Local AI work, which is a separate ticket. An Item Library link on a purchase order line.
