03 · Key custody

The provider constraint, stated correctly

03
No provider supports tenancy. That is not a property that exists. Every provider is one API key with one quota. The app can call any OpenAI-compatible endpoint from any form.

The real constraint is legal and economic, and it has two shapes.

ShapeWho holds the keyUsable for
Tenant’s own keyThe tenant, in private storageThe shipping path. Any document, any tenant.
Vendor pools one keyThe vendorA demo, an internal trial, or a paid plan.

The pooled shape fails twice. One free quota would serve every tenant, so the first busy day exhausts it. And several free tiers call themselves a trial or development service and forbid resale — the AMD Token Factory says so directly. That is the vendor’s key, not a missing provider feature.

10 · Next lane

Document intelligence — universal pipeline

10

DEC-32 / DEC-33 (2026-11-14) record the document-intelligence direction. One universal pipeline: intake and preservation → faithful extraction → normalization → reconciliation → deterministic calculation → human review → approved action. Evidence classification (extracted / calculated / inferred / matched / unverified / conflicting) is separate from workflow status. No AI-generated interpretation promotes itself to confirmed. Attachment intake is application-owned; Markdown from external AI is interchange only, never the business data model. The solar-pump BOQ and supplier-message reconciliation is the first acceptance case. NOTHING HERE IS IMPLEMENTED.
