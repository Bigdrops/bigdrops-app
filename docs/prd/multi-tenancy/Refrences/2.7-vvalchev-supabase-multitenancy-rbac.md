## Why This Reference Exists

This repository implements multi-tenant RBAC on Supabase with permission enums scoped to tenants, roles → permissions → groups hierarchy. It directly addresses BIGDROPS's §3 (permissions) + §6 (RLS) integration needs.

## Relevant Architecture / Patterns

- **Permission enum scoped to tenant** — permissions are defined as enumerated values, scoped to the tenant (workspace).
- **Roles → permissions → groups** — hierarchical: groups have roles, roles have permissions.
- **RLS integration** — permissions are checked at the database level via RLS policies.
- **Supabase-native** — designed specifically for Supabase's architecture.

## What BIGDROPS Should Borrow

- The **permission enum** concept — BIGDROPS could define ability keys as an enum for type safety.
- The **roles → permissions → groups** hierarchy — validates BIGDROPS §3's role → ability mapping.
- The **RLS integration** — permissions checked at the database level.

## What BIGDROPS Must NOT Adopt

- Single-level group model — BIGDROPS has workspace + entity (two levels).
- Specific permission enum values — BIGDROPS has its own ability taxonomy (§3).
- Any patterns that assume a different Supabase setup.

## Known Limitations

- Single-level group model — does not address workspace-entity hierarchy.
- No entity lifecycle (§8A) coverage.
- License may restrict usage in proprietary projects.

## Bottom Line

Good reference for permission enums and roles → permissions → groups hierarchy. The RLS integration pattern is directly applicable. Must be extended for two-level tenancy.
