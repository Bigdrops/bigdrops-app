## Why This Reference Exists

This repository demonstrates request-scoped tenant context strategies in a NestJS + Prisma stack. While BIGDROPS uses Supabase (not NestJS/Prisma), the tenant context propagation pattern is relevant.

## Relevant Architecture / Patterns

- **Request-scoped tenant context** — tenant context is set per-request and propagated through the application stack.
- **Prisma middleware** — tenant context is injected into every Prisma query via middleware.
- **RLS integration** — tenant context is set at the database level for RLS policies.
- **NestJS dependency injection** — tenant context is injected via NestJS's DI container.

## What BIGDROPS Should Borrow

- The **request-scoped tenant context** pattern — BIGDROPS edge functions should set tenant context once per request.
- The concept of **middleware-based context propagation** — BIGDROPS could create a Supabase client middleware that sets tenant context automatically.

## What BIGDROPS Must NOT Adopt

- NestJS as a framework — BIGDROPS uses React + edge functions.
- Prisma as an ORM — BIGDROPS uses Supabase client.
- NestJS-specific patterns (DI, middleware, guards).

## Known Limitations

- NestJS + Prisma specific; not applicable to BIGDROPS's stack.
- No entity lifecycle (§8A) coverage.
- Does not address two-level tenancy.

## Bottom Line

Conceptual reference for request-scoped tenant context. The pattern is transferable to BIGDROPS via Supabase client wrappers. Not directly applicable due to stack differences.
