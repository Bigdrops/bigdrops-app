## Why This Reference Exists

Agnite defines the canonical data retention pattern for multi-tenant SaaS: lifecycle metadata on entities (`IsArchived`, `DeleteAfter`), tenant-scoped purge jobs, and audit logging. This directly maps to BIGDROPS §8A (entity lifecycle).

## Relevant Architecture / Patterns

- **Lifecycle metadata on entities** — `IsArchived` (boolean), `DeleteAfter` (timestamp), status columns. BIGDROPS §8A uses `status` (active/archived/purging/purged) + `archived_at`.
- **Tenant-scoped purge jobs** — purge operations must always carry workspace/entity filters (same isolation rule as RLS).
- **Audit log** — every lifecycle transition (archive, restore, purge) must be logged.
- **Soft-archive → scheduled hard-delete → audit log** — the canonical lifecycle pattern.
- **Retention period** — configurable delay between archive and purge (BIGDROPS: 30 days).

## What BIGDROPS Should Borrow

- The **soft-archive → scheduled hard-delete → audit log** pattern — this is exactly what §8A defines.
- The **tenant-scoped purge jobs** principle — purge operations must carry workspace/entity filters, never run globally.
- The **retention period** concept — BIGDROPS's 30-day retention is a product choice; the pattern is generic.
- The **audit log** requirement — BIGDROPS `entity_lifecycle_audit` follows this pattern.

## What BIGDROPS Must NOT Adopt

- The specific metadata columns (`IsArchived`, `DeleteAfter`) — BIGDROPS uses `status` + `archived_at` per §8A.
- Generic purge job patterns that don't account for BIGDROPS's schema-per-entity model.
- Any patterns that weaken the 30-day retention gate — BIGDROPS §8A requires server-authoritative retention.

## Known Limitations

- Blog-level; may not cover all production edge cases.
- Does not address schema-per-entity purge (BIGDROPS's entity-specific schemas).
- No discussion of connection pooling or Supabase-specific constraints.

## Bottom Line

The canonical reference for data retention in multi-tenant SaaS. The soft-archive → hard-delete → audit pattern is directly applicable. BIGDROPS should validate its §8A implementation against this reference.
