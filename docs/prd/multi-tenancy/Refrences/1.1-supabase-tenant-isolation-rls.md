## Why This Reference Exists

BIGDROPS uses Supabase as its primary backend. §6 of the multi-tenancy PRD v2.1 requires Row-Level Security for tenant isolation. This article is a practical walkthrough of Supabase's RLS with Auth integration, covering the exact tools BIGDROPS already uses: Supabase Auth, `auth.uid()`, `auth.jwt()`, and Postgres RLS policies.

## Relevant Architecture / Patterns

- **Shared-schema tenancy** with `tenant_id` (BIGDROPS equivalent: `workspace_id` / `entity_id`) on every tenant-scoped table.
- **RLS policies** gate reads/writes at the database level — application code cannot accidentally bypass them.
- **Supabase Auth JWT claims** carry the tenant context; RLS policies read from `auth.jwt()` or a session variable set on connection.
- **INSERT/UPDATE/SELECT/DELETE** each gated by explicit USING and WITH CHECK clauses.
- **Client-side Supabase SDK** — user-facing queries run as the authenticated user, not as service role.

## What BIGDROPS Should Borrow

- The pattern of using `auth.jwt()` to extract tenant context in RLS policies — this is exactly how BIGDROPS already works.
- Teaching material: use this article as internal team documentation for onboarding developers to RLS concepts.
- The emphasis on **never exposing service role keys to the client**.

## What BIGDROPS Must NOT Adopt

- The article does not cover multi-level tenancy (workspace + entity). BIGDROPS has a two-level model; the article only shows single-level `tenant_id`.
- No mention of `FORCE ROW LEVEL SECURITY` — BIGDROPS must enforce this on all tables per §6.
- No discussion of connection pooling (PgBouncer) edge cases with `SET LOCAL` — BIGDROPS uses Supabase which runs PgBouncer.

## Known Limitations

- Tutorial-level depth; does not address production concerns like policy performance, index optimization for policy predicates, or BYPASSRLS risks.
- Does not discuss entity lifecycle (§8A) — archive/purge states are beyond the article's scope.

## Bottom Line

A good introductory reference for understanding how Supabase RLS works with Auth. Useful for team onboarding and as a conceptual baseline. BIGDROPS must go beyond this article's single-level approach to implement the two-level workspace+entity RLS required by v2.1 §6.
