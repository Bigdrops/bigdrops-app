## Why This Reference Exists

SociiLabs defines the four-table core for multi-tenant SaaS: `organizations`, `users`, `memberships`, `roles`. This is the canonical reference for workspace + membership architecture, which BIGDROPS §5 requires.

## Relevant Architecture / Patterns

- **Four-table core**:
  1. `organizations` (≈ workspaces) — the tenant entity.
  2. `users` — the user pool (shared across all tenants).
  3. `memberships` — many-to-many join between users and organizations.
  4. `roles` — role definitions scoped to organizations.
- **Name the tenant once** — the organization/workspace is the tenant; entities within it are second-level (BIGDROPS's §8A entity model).
- **Membership join table** — users belong to organizations through memberships, not by owning a `tenant_id` column.
- **Role per membership** — a user's role is scoped to the organization, not global.

## What BIGDROPS Should Borrow

- The **four-table core** pattern — BIGDROPS `workspaces`, `users`, `workspace_members`, `workspace_roles` map to this.
- The **membership join table** — validates BIGDROPS's membership model.
- The **role per membership** — validates BIGDROPS §3's workspace-scoped roles.
- The principle: **name the tenant once** — the workspace is the primary tenant; the entity is secondary.

## What BIGDROPS Must NOT Adopt

- Single-level organization — BIGDROPS has workspace + entity (two levels); SociiLabs only shows org + member.
- Any patterns that assume a different auth provider — BIGDROPS uses Supabase Auth.
- Generic multi-tenancy advice that doesn't account for BIGDROPS's entity lifecycle (§8A).

## Known Limitations

- Blog-level; may not cover all production edge cases.
- Single-level organization — does not address entity hierarchy.
- No entity lifecycle (§8A) coverage.

## Bottom Line

The four-table core is the canonical reference for workspace + membership architecture. Directly validates BIGDROPS's membership model. Must be extended for two-level tenancy.
