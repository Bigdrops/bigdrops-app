## Why This Reference Exists

Astuto implements multi-tenant workspaces on Supabase with a membership model, role-based access, and RLS. It provides a working reference for the workspace + member pattern that BIGDROPS §5 requires.

## Relevant Architecture / Patterns

- **Workspace + Member + Role** — three-table core: `workspaces`, `workspace_members`, with roles per membership.
- **RLS on workspace tables** — policies filter by workspace membership, not just `tenant_id`.
- **Supabase Auth integration** — uses Supabase Auth for user management, workspace-level access via RLS.
- **Next.js frontend** — same frontend framework family as BIGDROPS (React-based).

## What BIGDROPS Should Borrow

- The **workspace + membership + role** pattern — validates BIGDROPS's membership model.
- The RLS-on-workspace pattern — policies that check membership, not just `workspace_id` column.
- The Supabase Auth integration approach — how to wire Supabase Auth with workspace-level RLS.

## What BIGDROPS Must NOT Adopt

- The AGPL-3.0 license — BIGDROPS is proprietary; do not copy code from AGPL projects.
- The single-level workspace model — BIGDROPS has workspace + entity (two levels).
- Next.js-specific patterns — BIGDROPS uses Vite + React, not Next.js.
- Any patterns that assume direct Supabase client usage on the server — BIGDROPS uses edge functions.

## Known Limitations

- AGPL-3.0 licensed — code cannot be used in proprietary projects without licensing.
- Single-level workspace — does not address entity hierarchy.
- No entity lifecycle (§8A) coverage.
- May not address invitation flows — focus is on workspace membership.

## Bottom Line

A working reference for workspace + membership + RLS on Supabase. The pattern is applicable; the code is not (due to AGPL license). Use as a structural reference, not a code source.
