## Why This Reference Exists

Prisma demonstrates how to set tenant context with an ORM client extension — conceptually equivalent to `SET LOCAL` in raw Postgres. While BIGDROPS uses Supabase client (not Prisma), the pattern of setting tenant context at the client level is relevant.

## Relevant Architecture / Patterns

- **Client-level tenant context** — the ORM extension sets `app.current_tenant` on every query, ensuring RLS policies can read it.
- **Automatic context propagation** — the extension handles tenant context setup so application code doesn't have to.
- **RLS-compatible** — the pattern works with Postgres RLS; the tenant context is set at the database level, not filtered in app code.

## What BIGDROPS Should Borrow

- The concept of **automatic tenant context propagation** — BIGDROPS edge functions should set tenant context once per request, not on every query.
- The principle that **ORM/client extensions can simplify tenant context** — BIGDROPS could create a Supabase client wrapper that automatically sets tenant context.

## What BIGDROPS Must NOT Adopt

- Prisma as a dependency — BIGDROPS uses Supabase client.
- Prisma-specific patterns (client extensions, query middleware) — not applicable to BIGDROPS's stack.
- Any patterns that assume Prisma's query engine.

## Known Limitations

- Prisma-specific; not applicable to BIGDROPS's stack.
- No entity lifecycle (§8A) coverage.
- Does not address two-level tenancy.

## Bottom Line

Conceptual reference for automatic tenant context propagation. The pattern is transferable to BIGDROPS via a Supabase client wrapper. Not directly applicable due to stack differences.
