## Why This Reference Exists

Cinderblock is a Supabase + Next.js starter with **74 pgTAP RLS tests** against hostile multi-workspace fixtures. This is the most thorough publicly available RLS test suite for Supabase multi-tenant applications. It provides the verification pattern BIGDROPS needs for §6.

## Relevant Architecture / Patterns

- **74 pgTAP RLS tests** — comprehensive test coverage for multi-workspace isolation.
- **Hostile fixtures** — test data designed to prove that User A in Workspace 1 cannot read/write User B's data in Workspace 2.
- **Workspace + Member + Invite + Audit** — full membership lifecycle with RLS.
- **Supabase + Next.js** — same stack as BIGDROPS frontend.
- **RLS policies per operation** — explicit SELECT, INSERT, UPDATE, DELETE policies.

## What BIGDROPS Should Borrow

- The **pgTAP test approach** — 74 tests proving cross-tenant isolation. BIGDROPS should adopt this pattern for §6 verification.
- The hostile fixture strategy — design test data that actively tries to cross tenant boundaries.
- The workspace + member + invite pattern — validates BIGDROPS's membership model.
- The audit table pattern — matches BIGDROPS's `entity_lifecycle_audit` approach.

## What BIGDROPS Must NOT Adopt

- The single-level workspace model — BIGDROPS has workspace + entity (two levels).
- Next.js-specific patterns that assume the Pages Router — BIGDROPS uses React 19 + Vite, not Next.js.
- Any patterns that use service role on the client — BIGDROPS must never expose service role keys.

## Known Limitations

- Next.js-specific; not directly applicable to BIGDROPS's Vite + React stack.
- Single-level tenancy — does not address workspace-entity hierarchy.
- No entity lifecycle (§8A) coverage.
- The 74-test count may include tests for features BIGDROPS does not need (e.g., Next.js auth patterns).

## Bottom Line

The gold standard for RLS test coverage on Supabase. The pgTAP approach and hostile fixture strategy are directly applicable. BIGDROPS should create a similar test suite for its two-level RLS policies.
