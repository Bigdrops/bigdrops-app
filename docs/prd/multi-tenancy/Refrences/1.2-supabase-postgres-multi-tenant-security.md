## Why This Reference Exists

This is the **authoritative Supabase reference** for multi-tenant database security. BIGDROPS uses Supabase; this document defines how Supabase recommends implementing RLS for multi-tenant applications. It directly informs §6 of the multi-tenancy PRD v2.1.

## Relevant Architecture / Patterns

- **Auth-context RLS policies** using `auth.uid()` and `auth.jwt()` — exactly what BIGDROPS already uses.
- **`SET LOCAL` for tenant context** — `SET LOCAL app.current_tenant = '<tenant-id>'` in a transaction, then policies read from `current_setting('app.current_tenant')`.
- **USING vs WITH CHECK** separation: USING controls read access, WITH CHECK controls write validity.
- **Policy per operation** — separate SELECT, INSERT, UPDATE, DELETE policies for clarity.
- **FORCE ROW LEVEL SECURITY** — critical for preventing table-owner bypass.
- **Service role bypass warning** — service role bypasses RLS entirely; must never be used for user-facing queries.

## What BIGDROPS Should Borrow

- The `SET LOCAL` pattern for tenant context — BIGDROPS could adopt this for server-side operations (e.g., edge functions, cron jobs) where `auth.jwt()` is not available.
- The USING / WITH CHECK separation — BIGDROPS policies should clearly separate read and write gates.
- The `FORCE ROW LEVEL SECURITY` emphasis — this is non-negotiable for BIGDROPS §6.
- The architectural principle: **RLS is the isolation boundary**, application code is a convenience layer.

## What BIGDROPS Must NOT Adopt

- The single-level tenant model shown in the docs. BIGDROPS has workspace + entity (two levels); the docs only show single `tenant_id`.
- Defaulting to service role in server-side code — BIGDROPS must use the user's JWT context even in edge functions where possible.
- Skipping composite indexes on policy predicate columns — the docs mention this but don't emphasize it; BIGDROPS must index `workspace_id` + `entity_id` composites on all tenant-scoped tables.

## Known Limitations

- Focused on single-level tenancy; does not address workspace-entity hierarchy.
- Does not cover entity lifecycle (§8A) — archive/purge state transitions are not discussed.
- Connection pooling (`transaction` mode in Supabase) means `SET LOCAL` is the safe option — the docs don't explicitly address PgBouncer interaction.

## Bottom Line

The single most important reference for BIGDROPS §6 implementation. Every pattern in this document should be validated against BIGDROPS's two-level model. The USING/WITH CHECK separation, FORCE RLS, and tenant-context patterns are directly applicable.
