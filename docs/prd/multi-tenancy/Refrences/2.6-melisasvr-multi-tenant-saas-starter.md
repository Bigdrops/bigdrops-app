## Why This Reference Exists

This starter provides a complete org switcher, invitation flow, and role matrix on Supabase. It validates BIGDROPS's membership model and invitation patterns (§7-§9).

## Relevant Architecture / Patterns

- **Org switcher UI** — switching between organizations (workspaces).
- **Invitation flow** — invite → accept → membership creation.
- **Role matrix** — owner/admin/member roles with different permissions.
- **RLS policies** — row-level security on tenant-scoped tables.
- **Stripe integration** — billing per organization.

## What BIGDROPS Should Borrow

- The **org switcher** UI pattern — BIGDROPS's entity switcher follows this concept.
- The **invitation flow** — validates BIGDROPS §9 invite design.
- The **role matrix** — owner/admin/member roles.

## What BIGDROPS Must NOT Adopt

- Next.js-specific patterns — BIGDROPS uses Vite + React.
- Stripe integration patterns — BIGDROPS handles billing differently.
- The single-level org model — BIGDROPS has workspace + entity (two levels).
- Any patterns that assume service role on the client.

## Known Limitations

- Next.js-specific; not directly applicable to BIGDROPS's stack.
- Single-level organization — does not address entity hierarchy.
- No entity lifecycle (§8A) coverage.
- License may restrict usage.

## Bottom Line

Good reference for org switcher UI and invitation flow patterns. The role matrix validates BIGDROPS's role model. Must be adapted for Vite + React and two-level tenancy.
