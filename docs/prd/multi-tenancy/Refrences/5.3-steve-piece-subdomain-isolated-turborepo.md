## Why This Reference Exists

This starter demonstrates subdomain-based tenant isolation with capability RBAC and JWT claims. The subdomain routing pattern is relevant if BIGDROPS ever needs subdomain-based entity access.

## Relevant Architecture / Patterns

- **Subdomain routing** — tenant resolved from subdomain (e.g., `entity.workspace.bigdrops.com`).
- **Capability RBAC** — permission keys like `billing:update` rather than CRUD verbs.
- **JWT claims** — tenant context embedded in JWT tokens.
- **Turborepo** — monorepo structure for multi-package projects.

## What BIGDROPS Should Borrow

- The **capability RBAC** pattern — validates BIGDROPS §3's action-based abilities.
- The **JWT claims** approach — tenant context in JWT is relevant for BIGDROPS's edge functions.
- The subdomain routing concept — worth noting if BIGDROPS needs subdomain-based entity access in the future.

## What BIGDROPS Must NOT Adopt

- Subdomain routing as the default — BIGDROPS uses URL-based entity switching, not subdomains.
- Next.js-specific patterns — BIGDROPS uses Vite + React.
- Turborepo as a dependency — BIGDROPS uses Bun workspaces.
- Any patterns that assume a different auth provider.

## Known Limitations

- Next.js + Turborepo specific; not directly applicable to BIGDROPS's stack.
- Subdomain routing adds complexity; not needed for BIGDROPS's current requirements.
- No entity lifecycle (§8A) coverage.

## Bottom Line

Capability RBAC pattern is validated. JWT claims approach is relevant for edge functions. Subdomain routing is an interesting pattern but not needed for BIGDROPS's current requirements.
