## Why This Reference Exists

TurboStarter provides a mature Org + Member + Invitation triad pattern for Supabase multi-tenant apps. It explicitly addresses the unique `(org, user)` constraint, global vs org roles, and invitation flows — all relevant to BIGDROPS §5, §7-§9.

## Relevant Architecture / Patterns

- **Org + Member + Invitation triad** — the core pattern: organizations, memberships, and invitations as three interdependent tables.
- **Unique `(org, user)` constraint** — prevents duplicate memberships; BIGDROPS should adopt this.
- **Global user roles ≠ org roles** — a user's platform-level permissions differ from their org-level permissions. BIGDROPS §3 maps to this.
- **Invitation lifecycle** — token, expiry, accept with/without existing account.
- **Organization switcher** — UI for switching between organizations.

## What BIGDROPS Should Borrow

- The **unique `(org, user)` constraint** — BIGDROPS `workspace_members` should enforce this.
- The **global vs org roles** distinction — BIGDROPS user-level vs workspace-level permissions follow this pattern.
- The **invitation lifecycle** — token, expiry, accept flow. Validates BIGDROPS §9 invite design.
- The triad pattern itself — organizations, memberships, invitations.

## What BIGDROPS Must NOT Adopt

- Next.js / SvelteKit-specific patterns — BIGDROPS uses Vite + React.
- The single-level org model — BIGDROPS has workspace + entity (two levels).
- Any patterns that assume Clerk or other third-party auth — BIGDROPS uses Supabase Auth.
- Stripe billing integration patterns — BIGDROPS handles billing differently.

## Known Limitations

- Guide-level; may not cover all production edge cases.
- Single-level organization — does not address entity hierarchy.
- No entity lifecycle (§8A) coverage.

## Bottom Line

A solid structural reference for the Org + Member + Invitation triad. The unique constraint, global vs org roles, and invitation lifecycle patterns are directly applicable. BIGDROPS must extend for two-level tenancy.
