## The Platform Context

BIGDROPS is a Nigerian B2B business management platform. Stack: React + Vite + Tailwind v3 + Supabase + Vercel. Runtime is Bun — never npm or yarn. The operator (BIGDROPS) is a non-programmer who co-authors prompts and oversees architecture. Coding agents execute. Claude and ChatGPT act as architects. Gemini acts as attachment processor only.

The platform manages: Invoices, Quotations, Waybills (External + Internal), RFQ, CSR, Compliance Hub (VAT/WHT/Tax), Project Documents (PO, Receipt, Receiving Waybill, Other), Item Library. Most documents have JSON import capability allowing users to paste AI-extracted JSON to populate form fields.

## How JSON Import Works (The Mental Model)

The user has a paper or digital document (waybill, invoice, PO, etc.). They:
1. Open the import modal in the app
2. Copy the AI prompt (generated by the app)
3. Open an AI (Gemini, ChatGPT, etc.) via the "Open in AI" button
4. Paste their source document + the prompt into the AI
5. The AI returns structured JSON
6. User pastes the JSON back into the app
7. App validates and applies it to the form

The AI is a dumb extractor. It must never infer, group, or fabricate. The app does all calculations. The AI only reads what's explicitly on the page.

## Critical Architecture Decisions Made This Session

### 1. External and Internal Waybill are fully isolated
They are different domains. Not because their schemas are wildly different, but because document semantics > code reuse. They must never share prompts, adapters, schemas, or inference logic. Even if they look similar in the future, the isolation rule holds.

### 2. Groups are Invoice and Quotation only
No other module (Waybill, CSR, RFQ, Compliance Hub, Project Documents) supports groups. This rule must appear in every non-Invoice/Quotation prompt: "Do not create groups."

Invoice/Quotation Add mode received two anti-inference protections:
- **Prompt level:** Two explicit rules added to `generateImportPrompt()` — no groups from indentation/spacing, preserve exact item order
- **Apply level:** `hasScatteredGroups()` function in `apply.ts` — if the AI returns groups but all grouped items are clustered at the start, end, or in one block, groups are silently stripped. Only scattered groups (genuinely mixed with ungrouped items) are preserved.

### 3. `po_number` is a strictly labeled identifier field
The system has only one identifier field: `po_number`. Voucher Number is an alias — there is no separate voucher field. The rule: `po_number` may ONLY be filled if the source explicitly labels it as "PO Number", "Purchase Order Number", "P.O No", "Voucher Number", or "Voucher No". Any generic document number (Document No, Invoice No, Ref, Serial No) must produce `null`. This is a Tier 1 rule — AI's tendency to map any number to the nearest field is the primary failure mode.

### 4. Update mode is a row-level patch tool only
Groups are permanently ignored in Update mode. If the user wants to restructure groups, they use Add mode. Update mode received:
- Dynamic row range injected into prompt at copy time (`currentItemCount` parameter — no default, TypeScript enforces all callers)
- Schema-level row_number validation: `.int().positive()` with range check and duplicate detection via `.superRefine()`
- Overflow handling: >200 rows triggers warning toast and auto-truncates to first 200
- Overwrite confirmation dialog wired to `detectOverwriteTargets()`
- Empty-field retention warning in Update mode UI

### 5. Silent clipboard copy on Open in AI
When user clicks any AI provider in the dropdown, the prompt is silently written to clipboard (`navigator.clipboard.writeText(prompt)`) before `window.open`. No UI feedback for the clipboard write. This is a write operation — safe on all Android versions. The clipboard READ (Phase 8 detector) is the one that triggers Android 12+ system toasts, which is why Phase 8 uses an explicit button tap, not auto-read on focus.

### 6. Source is never locked to a specific input type
Prompts must never say "photographed" or "handwritten" or "scanned". A source is a source. PDF, plain text, photo, typed content — the AI doesn't need to know. Removing this constraint came from the waybill prompt review.

### 7. Prompt bloat is an anti-pattern
The waybill prompts initially came back with alias lists (5 aliases per field), signature detection rules, duplicate rule blocks, and unnecessary group rules. All stripped. The correct pattern: lean rules block (6-8 rules max), exact JSON shape, no aliases, no explanation of what fields mean unless the field name is genuinely ambiguous. The AI is not a student — it doesn't need a tutorial.

### Phase 2 — Invoice Add Mode Anti-Inference
**Files:** `src/domain/import/promptGenerator.ts`, `src/domain/import/apply.ts`

Two rules added to Add mode rules array in `generateImportPrompt()`:
1. Never infer groups from indentation, bullet style, or visual spacing — only from explicit section headings or category labels
2. Preserve the exact item order from the source document — do not reorder based on groups or any other criteria

`hasScatteredGroups()` function added to `apply.ts`:
- Builds true/false sequence (has group_id or not) for each item
- If all grouped items are at start, end, or all in one block → clustered → strip groups silently
- If grouped items are mixed with ungrouped in a scattered pattern → preserve groups
- Edge case confirmed correct: middle block (ungrouped, grouped×3, ungrouped) is scattered → preserved

## The Global Prompt Discipline Rules (Canonical)

These live in `JSON_IMPORT_DISCIPLINE_SPEC` in `promptGenerator.ts`. Every module's prompt must include them (modules can tailor but cannot weaken):

```
You are a strict JSON data extractor. Follow these rules without exception:
· Return ONLY data explicitly present in the source document.
· Never infer, guess, or fabricate values.
· Missing values MUST be null.
· Do not rename or reorder fields.
· Output MUST be valid JSON only.
· Groups are allowed ONLY if explicitly present in the source document.
· Never create groups from layout, indentation, or spacing.
· Each document type is independent (no cross-domain inference).
· The identifier po_number MUST be null unless the source explicitly labels it as PO/Voucher.
```

Additionally, every prompt must end with:
1. Wrap the JSON output in a code block
2. "Copy the JSON above and paste it back into the app."

## Lessons Learned (For Future Sessions)

1. **Never approve based on code review alone.** Phase 0 was "approved" based on the agent's code review, then failed on real device. Always ask "have you tested on device?" before marking a phase complete.

2. **Mobile + Radix inside Sheet = avoid.** Radix Popover, DropdownMenu, and similar portal-based components fail inside shadcn Sheet on mobile touch. Native elements or non-portal components are more reliable.

3. **Agents will fix things without being asked.** The Update mode reconnection happened because the agent found a broken thing and fixed it instead of reporting. Build "report only" enforcement into every audit prompt.

4. **Prompt bloat is the enemy.** Agents write what they're given permission to write. Specific, lean prompts produce specific, lean outputs. Open-ended prompts produce overengineered outputs with aliases, duplicate rules, and source-type restrictions.

5. **DeepSeek/Minimax challenges are usually right.** When Minimax pushed back on the iframe diagnosis, he was correct. When he challenged the clipboard fallback framing, he was correct. The right move is to investigate before dismissing.

6. **The `currentItemCount` no-default rule is critical.** If a default of `0` or `undefined` is allowed, the Update mode prompt would generate "Valid row_numbers: 1 through 0" which is meaningless. TypeScript enforcement of explicit caller-passing is the right call.

7. **"A source is a source."** Never lock a prompt to a specific input medium. The AI doesn't need to know if the source is a photo, PDF, or typed text. Locking it creates unnecessary rejection of valid inputs.
