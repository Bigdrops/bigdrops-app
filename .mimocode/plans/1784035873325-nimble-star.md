# PR-X: Global Long-Running Action Feedback System

## Problem

~150 long-running operations across BIGDROPS lack consistent loading feedback. Users click buttons for conversions, PDF generation, saves, archives, and deletes with no visual confirmation that work started. The application appears frozen during async operations.

## Strategy

**No new components.** The `Button` already supports `loading`. The `feedback` API already supports progress toasts. The work is wiring existing primitives into handlers that lack loading states.

### Standard Pattern (applied to every handler)

```tsx
// 1. Add state
const [loading, setLoading] = useState(false);

// 2. Wrap handler
const handleAction = async () => {
  setLoading(true);
  try {
    await doAsyncWork();
    feedback.success("Done");
  } catch (error) {
    feedback.error("Failed");
  } finally {
    setLoading(false);
  }
};

// 3. Wire to button
<Button loading={loading} onClick={handleAction}>Action</Button>
```

For operations >1s, add application-level toast:
```tsx
const handleAction = async () => {
  setLoading(true);
  const toastId = feedback.loading("Creating Invoice...");
  try {
    await doAsyncWork();
    feedback.dismiss(toastId);
    feedback.success("Invoice created!");
  } catch (error) {
    feedback.dismiss(toastId);
    feedback.error("Failed");
  } finally {
    setLoading(false);
  }
};
```
