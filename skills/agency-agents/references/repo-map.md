# Repository map

This skill is based on the public repository [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents), which is organized as a library of markdown-based specialist agents.

## What the repository provides

- A broad catalog of role prompts grouped by function.
- Practical categories such as engineering, design, marketing, analytics, and content.
- Agent files intended to be mixed and matched for client or product work.

## Useful categories

- `engineering/`: software engineering, architecture, code review, QA, and related build roles.
- `design/`: product design, UX, UI, visual direction, and related design roles.
- `marketing/`: growth, SEO, acquisition, positioning, and campaign-oriented roles.
- `content/`: writing, messaging, copy, and editorial roles.
- `analytics/`: performance analysis, measurement, and research-adjacent roles.
- `product/` or strategy-oriented folders: planning, prioritization, and roadmap roles when present.

## Selection heuristics

- If the task is implementation-heavy, start with an engineering role.
- If the task is about user flows, interface quality, or polish, start with design.
- If the task is traffic, reach, ranking, or conversion, start with marketing or SEO.
- If the task is wording, narrative, or brand voice, start with content or copywriting.
- If the task is performance, metrics, or learning from data, start with analytics.

## Recommended role combinations

- Product concept or feature shaping: strategist plus researcher or analytics.
- Frontend feature delivery: frontend engineer plus designer, with accessibility or QA support if risk is high.
- Content-led landing page: copywriter plus designer, adding SEO only when discovery matters.
- Release hardening: engineer plus QA or code reviewer.

## How to use this snapshot

- Use this file to choose candidate roles quickly.
- Do not assume the snapshot is exhaustive.
- When the user needs a specific upstream agent prompt, fetch only that file and summarize the relevant operating guidance.
