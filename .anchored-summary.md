> Created: 2026-06-26

## Goal

Comprehensive READ-ONLY audit of document form-related files covering form line items, mobile cards, shared forms, UI inputs, hooks, observers, viewport/keyboard handling, and CSS viewport units. Understand how the shared document form infrastructure works before any modifications.

## Architecture Map

### Shared Document Form Shell (`SharedDocumentForm.tsx`)
- **Path:** `src/components/document/SharedDocumentForm.tsx`
- Orchestrates all form sections: Header, CommercialTerms, LineItems, NotesTerms, Totals, Footer
- Lazy-loads `ColumnManager` and `JsonItemsImportSheet`
- All invoice/quotations render through this shell (verified by `sharedDocumentFormRegression.test.js`)

## Key Findings

1. **No dedicated `MobileForm*` component** — mobile form composed from `mobileFormPrimitives`, `MobileItemCard`, `MobileGroupCard`, and `mobileFormHelpers`
2. **No `SharedForm` or `DocumentForm` named component** — shared form entry point is `SharedDocumentForm.tsx`
3. **No `ResizeObserver` or `IntersectionObserver` usage** anywhere in source
4. **`MutationObserver` only used for theme/mode detection** (Android system bars, circuit board)
5. **`KeyboardAwareness`** is the sole mechanism for keyboard-aware layout, bound to `visualViewport` events
6. **`transition-all` is sparse** — none in CSS, limited Tailwind usage in specific components
7. **`100dvh` preferred** in global CSS, with `100vh` fallback in legacy CSS modules
8. **Item field policy separates invoice (monetary) from waybill (non-monetary)** fields — crucial for spawn transforms
